How to Get Input from a Real Machine

1. Model Architecture (Automatic)

Every HuggingFace model ships a config.json that contains all architecture hyperparameters. Our pipeline reads these directly:

# From HuggingFace Hub or local checkpoint
from transformers import AutoConfig
config = AutoConfig.from_pretrained("meta-llama/Llama-2-7b-hf")

# Extract what LLMOpt needs:
pipeline_input = {
    "num_layers": config.num_hidden_layers,      # 32
    "hidden_size": config.hidden_size,            # 4096
    "num_attention_heads": config.num_attention_heads,  # 32
    "num_kv_heads": config.num_key_value_heads,   # 32
    "intermediate_size": config.intermediate_size, # 11008
    "vocab_size": config.vocab_size,              # 32000
}

2. GPU Hardware (Automatic)

GPU specifications can be queried at runtime using NVIDIA's management libraries:

# Using pynvml (NVIDIA Management Library)
import pynvml
pynvml.nvmlInit()
handle = pynvml.nvmlDeviceGetHandleByIndex(0)

gpu_name = pynvml.nvmlDeviceGetName(handle)      # "NVIDIA A100-SXM4-80GB"
gpu_mem  = pynvml.nvmlDeviceGetMemoryInfo(handle) # .total = 85899345920

# Or via torch
import torch
torch.cuda.get_device_name(0)                     # "NVIDIA A100-SXM4-80GB"
torch.cuda.get_device_properties(0).total_memory   # 85899345920

# Bandwidth and TFLOP/s come from our datasheet-based preset table,
# keyed by the device name string above.

3. Workload Parameters (User or Profiler)

Workload parameters come from two sources:

  • Deployment config: batch size, max context length, precision — set by the serving team
  • Production traffic: prompt lengths, generation lengths, prefix sharing patterns — measured from request logs
# Example: extract prompt-length distribution from logs
import numpy as np
prompt_lengths = [len(req.tokens) for req in serving_logs]
p50, p95 = np.percentile(prompt_lengths, [50, 95])
# Use p95 as the "sequence_length" for worst-case planning

4. Real Prompts for Prefix Sharing

The prefix-sharing pass uses actual prompt token sequences to build a radix trie and find shared prefixes. Pass real request batches:

# Real prompts from your serving system
pipeline_input["prompts"] = [
    "You are a helpful assistant. Context: ...",
    "You are a helpful assistant. Question: ...",
    "You are a helpful assistant. Summarize: ...",
]
# The trie finds "You are a helpful assistant." is shared
# → KV for those tokens computed once, reused by all 3 requests

2. Decision Guide

Use the pipeline output to configure your serving engine:

# Example: applying LLMOpt recommendations to vLLM
# If paged_kv selected → already default in vLLM
# If int8_kv selected → launch with:
vllm serve meta-llama/Llama-2-7b-hf \
  --kv-cache-dtype fp8 \
  --max-model-len 4096

# If prefix_share selected → enable APC:
vllm serve meta-llama/Llama-2-7b-hf \
  --enable-prefix-caching

# If fusion selected → FlashAttention is used by default
# If split_kv selected → automatic in Flash-Decoding

3. Capacity Planning

The memory analysis tells you exactly how many concurrent requests your GPU can handle:

  • max_batch from P2 → maximum concurrent requests before OOM
  • TPOT (time per output token) → per-request latency SLA
  • Throughput (tok/s) → aggregate serving capacity
  • TTFT (time to first token) → user-perceived latency

4. What This Pipeline Cannot Do (Theoretical Limits)

This is an analytical compiler optimization pipeline, not a runtime framework:

  • It does not execute GPU kernels — all numbers are roofline estimates at 100% hardware utilization
  • It does not modify model weights — the INT8 KV pass simulates quantization error but doesn't produce quantized checkpoints
  • It does not generate CUDA code — the auto-tuner searches the configuration space analytically; Triton or CUTLASS would implement the actual kernel
  • Real performance will be 60–85% of roofline due to cache effects, warp scheduling, memory coalescing, and PCIe overhead

To bridge the gap: feed the chosen tile configuration into a Triton kernel template, benchmark it on the target GPU, and compare against the roofline prediction.
