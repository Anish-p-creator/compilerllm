    Feeding it a real machine
    the three inputs, and where each comes from
    
      
    
        
    1
    Model architecture
    Every Hugging Face checkpoint ships a config.json. Read layers, heads, KV heads, hidden and FFN size straight from it.
    

    from transformers import AutoConfig
c = AutoConfig.from_pretrained("meta-llama/Llama-2-7b-hf")
cfg = dict(layers=c.num_hidden_layers,
           heads=c.num_attention_heads,
           kv_heads=c.num_key_value_heads,
           hidden=c.hidden_size,
           ffn=c.intermediate_size)
    
        
    2
    GPU hardware
    Query the device with NVML and map its name to a datasheet preset (bandwidth, TFLOP/s). The detect mine button in Studio calls /api/detect, which does exactly this.
    

    import pynvml
pynvml.nvmlInit()
h = pynvml.nvmlDeviceGetHandleByIndex(0)
name = pynvml.nvmlDeviceGetName(h)
mem  = pynvml.nvmlDeviceGetMemoryInfo(h).total
    
        
    3
    Workload
    Batch size and precision come from the deployment config; prompt and output lengths come from request logs (plan for p95, not the mean).
    

    import numpy as np
lens = [len(r.prompt_tokens) for r in logs]
p95  = int(np.percentile(lens, 95))
requests.post("http://localhost:5000/api/optimize",
              json={"sequence_length": p95, ...})
    
      
    
    
    

    
    
      
    What this is — and isn't
    
      
    
        
    It is an ahead-of-time planner: an analytical compiler that predicts which optimizations pay off for a model × GPU × workload, before you spend GPU hours.
    
        
    It doesn't run kernels or emit CUDA. Numbers are roofline estimates; expect real systems to reach ~60–85% of them.
    
        
    Close the loop by benchmarking the recommended config (e.g. the auto-tuner's tile in a Triton template) on the target GPU and feeding measured numbers back.
